DOCUMENTAÇÃO COMPLETA DO PROJETO MANTHAM / MATH GAME
Data da documentação: 27/10/2026

============================================================
1. IDENTIDADE DO PROJETO
============================================================

Mantham (Math Game) é uma plataforma educacional web voltada ao Ensino Fundamental II, principalmente aos alunos do 6º ao 9º ano. O objetivo é ensinar matemática por meio de jogos, trilhas progressivas, pontuação, estrelas, desbloqueio de fases, avatar e recompensas.

Experiência proposta:
- Aprendizado visual e progressivo.
- Conteúdo dividido por anos letivos.
- Jogos matemáticos com diferentes níveis de dificuldade.
- Progresso salvo para usuários autenticados.
- Modo livre para prática sem vínculo com a trilha.
- Personalização visual da plataforma.
- Recursos de acessibilidade.
- Perfil com estatísticas e diagnóstico do desempenho.

O projeto recebeu o nome comercial Mantham, enquanto Math_Game é usado como nome da estrutura do diretório, banco de dados e parte dos arquivos técnicos.

============================================================
2. TECNOLOGIAS UTILIZADAS
============================================================

Front-end:
- HTML5.
- CSS3 com Flexbox, Grid, variáveis customizadas, pseudo-elementos e responsividade.
- JavaScript Vanilla.
- SVG para gráficos, mapas, ícones e elementos visuais.
- Fetch API, async/await e JSON.
- LocalStorage para algumas preferências locais e caches.
- SessionStorage para dados temporários específicos de navegação.
- ARIA e navegação por teclado em controles importantes.

Back-end:
- PHP tradicional sem framework completo.
- Sessões PHP.
- PDO para acesso ao MySQL/MariaDB.
- Consultas preparadas para evitar SQL Injection.
- APIs PHP no formato JSON.
- Password Hash do PHP, com bcrypt.
- PHPMailer disponível na pasta vendor para funcionalidades relacionadas a mensagens eletrônicas.

Infraestrutura:
- Servidor Apache com XAMPP ou ambiente PHP compatível.
- MySQL/MariaDB.
- Windows, PHP e Apache no ambiente local.

============================================================
3. ARQUITETURA GERAL
============================================================

A aplicação segue uma arquitetura simples baseada em páginas PHP, módulos JavaScript e endpoints JSON.

Estrutura lógica:

1. Uma página PHP verifica a sessão.
2. O PHP monta o HTML inicial.
3. O tema central é carregado por tema.js.
4. O JavaScript específico da página busca dados ou inicia interações.
5. Operações sensíveis são enviadas para api/*.php.
6. Os endpoints PHP validam os dados, acessam MySQL e retornam JSON.
7. JavaScript atualiza a interface sem recarregar toda a página.

Fluxo típico:

Usuário -> Página PHP -> JavaScript -> API PHP -> PDO -> Banco MySQL -> JSON -> Atualização da interface

Características da organização:
- Cada jogo tem sua própria pasta.
- Recursos compartilhados ficam em includes/.
- APIs de autenticação ficam em api/auth/.
- APIs de progresso ficam em api/progresso/.
- APIs da loja de avatares ficam em api/avatar/.
- O estilo compartilhado fica em tema.css.
- A aplicação de preferências compartilhadas fica em tema.js.

============================================================
4. FLUXO PRINCIPAL DO USUÁRIO
============================================================

1. O usuário entra em index.php.
2. A página apresenta o projeto e os conteúdos dos 6º ao 9º anos.
3. O visitante pode:
   - Criar conta.
   - Entrar.
   - Acessar a página de jogos.
   - Entrar em modo visitante, dependendo da página.
4. Após o login, o usuário é identificado pela sessão.
5. No dashboard Home, são exibidos:
   - Modo livre.
   - Último jogo acessado.
   - Trilha atual.
   - Estatísticas do perfil.
6. O usuário pode escolher uma trilha por ano letivo.
7. Cada fase ativa um jogo específico.
8. Ao concluir, estrelas e pontuação são calculadas.
9. O progresso é enviado ao banco quando o usuário está autenticado.
10. A próxima fase ou próximo ano pode ser desbloqueado.
11. O perfil apresenta evolução, estrelas, patentes e avatares.
12. Configurações permite personalizar tema, tonalidade e acessibilidade.

============================================================
7. PONTUAÇÃO, ESTRELAS E DESEMPENHO
============================================================

Os jogos produzem pontuação, acertos, erros e tempo de jogo. O sistema transforma isso em estrelas, normalmente de 0 a 3.

Conexão entre resultado e trilha:
- Estrelas iguais ou maiores que 1 podem desbloquear a próxima fase.
- Pontuação máxima é preservada.
- Estrelas nunca são reduzidas por um novo resultado inferior.
- Vezes jogadas são incrementadas.
- histórico_acessos registra a atividade.
- Uma fase 20 concluída pode desbloquear o primeiro item do próximo ano.

O modo livre:
- Mantém recorde local em LocalStorage.
- Não altera o desbloqueio da trilha automaticamente.
- Permite praticar sem compromisso com o progresso permanente.

O API de progresso recebe campos como:
- ano.
- fase.
- fase_id.
- jogo_id.
- pontuação.
- estrelas.
- tipo de acesso.
- título da fase.

Arquivo principal: api/progresso/salvar.php.

============================================================
8. TRILHA DE 20 FASES POR ANO
============================================================

Cada ano possui 20 fases, formando 80 fases no banco:

6º ano — Floresta dos Números:
- Predominância dos jogos 4 e 1.
- Trabalha sucessores, antecessores, frações iniciais e operações básicas.

7º ano — Deserto das Frações & Estatística:
- Alterna jogos 1 e 2.
- Trabalha frações e interpretação gráfica.

8º ano — Galáxia da Geometria:
- Predominância dos jogos 3 e 2.
- Trabalha formas, área, perímetro e gráficos.

9º ano — Cidadela dos Mestres:
- Mistura todos os quatro jogos principais em progressão gradual.
- Representa uma etapa mais avançada da trilha.

Estado das fases:
- Bloqueada.
- Atual/disponível.
- Concluída.
- Concluída com resultado perfeito, quando aplicável.

A biblioteca includes/validador_fase.php ajuda a validar se a fase solicitada corresponde ao contexto correto do usuário.

9. AUTENTICAÇÃO
============================================================

O sistema usa:
- Senha armazenada por hash bcrypt.
- Prepared statements PDO.
- Sessão PHP.
- Token CSRF.
- Rate limiting de tentativas de login.
- Cookies persistentes seguros.
- Regeneração de ID da sessão.
- Logout e revogação de tokens.

Arquivos principais:
- api/auth/register.php — criação de conta.
- api/auth/login.php — autenticação.
- api/auth/logout.php — encerramento da sessão.
- api/auth/session.php — consulta da sessão atual.
- includes/sessao.php — inicialização, restauração e proteção de sessão.
- includes/csrf.php — geração e validação de token CSRF.
- includes/senha.php — hashing e verificação de senha.
- includes/tentativas_acesso.php — controle de tentativas excessivas.

O login persistente usa seletor e validador separados. O token persistente é armazenado em cookie; a parte hash do validador fica associada ao banco. O login gera cookie HttpOnly, SameSite=Lax e Secure quando o ambiente usa HTTPS.

12. PERFIL, PATENTES E AVATARES
============================================================

O perfil calcula informações como:
- Patente atual.
- Pontuação total.
- Total de estrelas.
- Saldo disponível.
- Fases concluídas.
- Fases perfeitas.
- Desempenho por jogo.
- Avatares adquiridos.

Regra de moeda:
- Estrelas conquistadas nas fases podem ser usadas para comprar avatares.
- O custo atual padrão de cada avatar é 10 estrelas.
- Foto 1 é o avatar padrão gratuito.

Fotos:
- Arquivos ficam em fotos/.
- A API dados.php varre a pasta automaticamente.
- São considerados arquivos fotoN.webp.
- novos arquivos aparecem conforme novos números e o WebP está disponível.
- comprar.php valida o arquivo enviado e permite a compra.
- equipar.php verifica posse ou padrão gratuito antes de salvar.

Endpoints:
- api/avatar/dados.php — lista avatares, saldo, compras e avatar atual.
- api/avatar/comprar.php — compra.
- api/avatar/equipar.php — equipe uma foto já desbloqueada.

20. FRASES ÚTEIS PARA APRESENTAR
============================================================

Sobre o projeto:
"O Mantham transforma exercícios de matemática em uma jornada com fases, jogos, estrelas e feedback visual."

Sobre a arquitetura:
"O front-end é feito com HTML, CSS e JavaScript. As operações sensíveis são feitas por APIs PHP e o banco MySQL é acessado pelo PDO."

Sobre segurança:
"Senhas são protegidas por hash, consultas sensíveis usam PDO Prepared Statements e a sessão utiliza token CSRF e cookies seguros."

Sobre os jogos:
"Cada jogo é independente, mas todos podem enviar o resultado para o mesmo sistema central de progresso."

Sobre as trilhas:
"Cada ano possui 20 fases. Concluir uma fase libera a próxima e encerrar uma trilha pode liberar o próximo ano."

Sobre o perfil:
"O perfil agrega desempenho, estrelas, fases concluídas, recordes e diagnóstico pedagógico."

Sobre avatares:
"Novas fotos são detectadas automaticamente pela API e podem ser adquiridas com estrelas conquistadas nos jogos."

Sobre acessibilidade:
"A plataforma oferece tema escuro, tonalidades de cor, modos para diferentes tipos de daltonismo e alto contraste."
